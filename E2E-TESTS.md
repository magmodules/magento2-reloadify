## Auth (`api/auth.spec.ts`)

Every Reloadify route except restore-cart requires Magmodules_Reloadify::webapi. Without a token, and with the token of an integration that lacks that resource, Magento answers 401. Reloadify connects with the integration's access token as a Bearer token. Since Magento 2.4.4 an integration token is only accepted that way when Stores > Configuration > Services > OAuth > "Allow OAuth Access Tokens to be used as standalone Bearer tokens" is on; configure-reloadify.sh switches it on, and the last test here shows what happens on a shop where it is off.

1. Authentication › every GET route answers 401 without a token
2. Authentication › every GET route answers 401 for an integration without the Reloadify resource
3. Authentication › every GET route answers 200 with the token from bin/magento reloadify:integration
4. Authentication › restore-cart is the only anonymous route
5. Authentication › integration token as Bearer token with the Magento default configuration › is refused with 401 while enable_integration_as_bearer is off

## Cart Restore (`api/cart-restore.spec.ts`)

The link in the abandoned cart e-mail (reloadify/cart/restore?id=...) and its Web API counterpart for headless storefronts (POST /V1/reloadify/restore-cart/:encryptedId). Both put an abandoned quote back in use; neither may revive a quote that already became an order, and a link that is missing or broken lands on the homepage instead of an error page. A visitor gets the quote itself only when it is theirs. A guest opening a customer's link gets a new guest quote with the same items and the customer's quote is closed: Magento's guest cart endpoints refuse a quote that belongs to a customer, so the cart page would otherwise stay empty.

6. Cart restore link › an inactive quote becomes active again and the shopper lands on the cart
7. Cart restore link › a customer's cart opened by a guest lands on the cart and the customer's quote is closed
8. Cart restore link › a quote that became an order stays inactive and the shopper lands on the homepage
9. Cart restore link › a link without id redirects to the homepage without an error
10. Cart restore link › a link with a garbage id redirects to the homepage without an error
11. Cart restore Web API › an inactive quote becomes active again
12. Cart restore Web API › an encrypted id that contains "/" is accepted in the path
13. Cart restore Web API › a customer's cart restored anonymously comes back as a new guest cart with the same items
14. Cart restore Web API › a quote that became an order stays inactive
15. Cart restore Web API › a garbage id is refused without a server error

## Schema (`api/schema.spec.ts`)

Magento's REST schema is generated from the service interfaces' docblocks. A docblock type Magento cannot resolve, such as a class name without its namespace, makes the whole schema endpoint answer 500, for every module in the shop. The schema must answer and list every Reloadify route.

54. REST schema › /rest/all/schema?services=all answers 200 and lists every reloadify route
